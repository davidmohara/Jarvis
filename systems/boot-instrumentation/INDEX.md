## Core Instrumentation System

### Measurement Script
**`systems/boot-instrumentation/measure.py`**
- Python script to measure accumulated-context size
- Breaks down by field (phase1, phase2, verification, etc.)
- Compares before/after states
- Usage: `python3 measure.py measure-state workflows/boot/state.yaml`

### Measurement Workflow Step
**`workflows/boot/steps/step-02.5-measure-phase2.md`**
- Runs automatically after Phase 2 data gathering
- Non-blocking (won't stop boot if it fails)
- Calls measure.py and surfaces top 5 bloat sources
- Output: measurement snapshot to `systems/boot-instrumentation/measurements/`

## Data Files

### Unified Calendar (Generated)
**`data/calendar-unified.json`**
- Generated by step 01.5
- Contains 4-day calendar window from M365
- Consumed by boot step-02 Task G and morning-briefing steps 01 & 03

### Measurement Snapshots (Generated)
**`systems/boot-instrumentation/measurements/measurement-state-{timestamp}.json`**
- Generated by step 02.5 after each boot run
- Contains: total size, field breakdown, estimated tokens
- Use for comparison across runs

**`systems/boot-instrumentation/measurements/comparison-{timestamp}.json`**
- Generated when comparing two measurements
- Shows: reduction_bytes, reduction_pct, before/after breakdown

### Backups (Manual)
**`systems/boot-instrumentation/backups/{date}-pre-optimization.yaml`**
- Backup of `workflows/boot/state.yaml` before making changes
- Use as baseline for comparison script

## Workflow Integration Points

### Boot Workflow Sequence
```
Step 01: Load Context
    ↓
Step 01.5: Unified Calendar Pull ← NEW
    │ Writes: data/calendar-unified.json
    ↓
Step 02: Gather Data (Phase 2)
    │ Task G reads calendar-unified.json
    ↓
Step 02.5: Measure Phase 2 ← NEW
    │ Writes: measurement snapshot
    ↓
Step 03-07: Continue as normal
```

### Data Files
```
Step 01.5 writes:
  └─ data/calendar-unified.json

Step 02.5 writes:
  └─ systems/boot-instrumentation/measurements/measurement-state-{ts}.json

Boot step-02 reads:
  └─ data/calendar-unified.json

Morning briefing steps 01 & 03 read:
  └─ data/calendar-unified.json
```

## How to Use

### 1. Establish Baseline (First Time)
```bash
# Read these first:
cat systems/boot-instrumentation/README.md
cat systems/boot-instrumentation/CALENDAR-CONSOLIDATION.md

# Then run boot workflow normally
# Step 01.5 will create data/calendar-unified.json
# Step 02.5 will measure and write snapshot

# Check results:
cat $(ls -t systems/boot-instrumentation/measurements/measurement-state-*.json | head -1) | jq .
```

### 2. Validate First Run
```bash
# Follow the checklist:
cat systems/boot-instrumentation/FIRST-RUN-CHECKLIST.md

# Verify calendar consolidation worked:
ls -lh data/calendar-unified.json  # Should exist
grep "calendar-unified" workflows/boot/state.yaml  # Should mention file
```

### 3. Optimize Next Bloat Source
```bash
# Read optimization guide:
cat systems/boot-instrumentation/OPTIMIZATION-SUMMARY.md

# Identify next-largest field from measurement:
cat $(ls -t systems/boot-instrumentation/measurements/measurement-state-*.json | head -1) | jq '.field_breakdown | .[0:10]'

# Backup current state:
cp workflows/boot/state.yaml systems/boot-instrumentation/backups/2026-07-01-before-email-consolidation.yaml

# Apply consolidation pattern to next field (email, meeting-context, etc.)
# Run boot again
# Compare measurements:
python3 systems/boot-instrumentation/measure.py compare \
  systems/boot-instrumentation/backups/2026-07-01-before-email-consolidation.yaml \
  workflows/boot/state.yaml
```

### 4. Track Progress
```bash
# Update tracking.json with each optimization:
# - measurement_id
# - before/after sizes
# - reduction %
# - next target field
```

## Key Metrics

### Before Calendar Consolidation
- Phase 2 total: 500+ KB
- M365 calendar calls: 3
- Calendar context: 200+ KB
- Estimated tokens: 125,000+
- First-run compaction: YES

### After Calendar Consolidation
- Phase 2 total: 100-150 KB (target)
- M365 calendar calls: 1
- Calendar context: 40 KB
- Estimated tokens: 25,000-37,000
- First-run compaction: NO (target)

### Overall Optimization Target
- Phase 2 total: < 150 KB
- No first-run context window compaction
- All data integrity maintained
- No breaking changes to downstream steps
