## Patterns Identified

1. **Daily-review phantom success (11 runs, high confidence):** Eleven daily-review runs claim `status: success` but score 0/8 or 1/8 on assertions because the review output file for that date was never written. All 11 are scheduled 02:xx UTC runs. The Jul 10 interactive run scored 1.0 (A). The Jul 17 02:xx UTC run scored 7/8 (B) — the exception that shows the pattern is not universal but tied to specific failure conditions in the scheduled runner.

2. **Working memory write systematically skipped (14 runs):** The `daily_review-wm-written` assertion fails on 14 records. Even runs that successfully write the review file (e.g., LJKKIQ Jul 14) skip the working memory write. This is a separate failure from the phantom-success pattern — the review can succeed while WM is still skipped.

3. **daily-review state.yaml multi-document YAML (12 assertion failures):** The `daily-001-state-complete` assertion fails on 12 records due to a multi-document YAML structure in `workflows/daily-review/state.yaml`. The assertion evaluator now handles this, but the underlying state file should be cleaned up.

4. **system-eval close-eval-record.py session_id mismatch (2 confirmed occurrences):** The Jul 11 run produced a spurious record (8DNQT4) with fabricated synthetic step data. The Jul 18 run has the same risk. This is a known defect noted in state.yaml from the Jul 11 run.

5. **No working definition for general-purpose, genius-spark-meeting-prep, claude-code-guide (4 records affected):** These workflow types have no assertion definition file. Scores default to neutral (0.5) for assertion_rate, which inflates apparent scores for aborted runs.

6. **Tier 4 feedback gap (56/63 records unrated):** The scoring formula weights controller feedback at ~12% of composite score. With 89% of records unrated, the feedback component contributes almost nothing to score differentiation. The signal that does exist (3 negative ratings) is concentrated in older records and not being used to surface improvement patterns.

7. **Daily-review grade trend improving post-Jul-10 (early signal):** The three most recent non-phantom runs (Jul 14 B, Jul 15 C, Jul 17 B) show grades clustering in B-C range with substantive output. This contrasts with the Jun-Jul run of F grades. Jul 10 interactive (A, score 1.0) was the inflection point.

## Recommendations

1. **Fix the daily-review scheduled runner — phantom output (highest priority):** The 02:xx UTC scheduled runs are completing state.yaml without writing the review file. Investigate `workflows/daily-review/workflow.md` to confirm the output-write step is not being skipped on a timeout or tool failure. Add an explicit output-file-existence check before closing workflow status as `success`. Eleven records document this failure.

2. **Fix the working memory write step in daily-review:** Even on runs that successfully write the review file, the WM write is being skipped. This is a separate fix from recommendation 1 — the write step may be running after a timeout window closes. Audit `step-06` (or the equivalent close step) of the daily-review workflow for the WM write path.

3. **Clean up `workflows/daily-review/state.yaml` multi-document YAML:** The file contains two YAML documents separated by `---`. The assertion evaluator now handles this gracefully, but the underlying file should be normalized to a single document to prevent future tooling issues.

4. **Fix `close-eval-record.py` session_id mismatch:** The script creates a new record instead of closing the existing stub when the Cowork session_id doesn't match. Add a `--force-id` flag or explicit stub-path parameter so the script can close the correct record regardless of session context. See `err` log from Jul 11 run and `spurious_record: eval-20260711T041415-8DNQT4`.

5. **Add assertion definitions for general-purpose, genius-spark-meeting-prep:** Even a minimal definition (1-2 checks) would give these records meaningful Tier 2 data. Currently their scores are artificially neutralized.

6. **Prompt David for Tier 4 feedback on recent low-scoring runs:** `eval-20260718T021141-QZAG77` (daily-review, score 0.508, F), `eval-20260717T141642-SSSC8G` (general-purpose aborted, 0.300, F), and `eval-20260711T021151-T7AGFP` (daily-review, 0.508, F) are the three lowest-scoring records from the past 7 days with no feedback rating. Controller signal on these would improve the scoring model's calibration.

7. **Investigate remarkable-upload grade mismatch:** One run (E747AF) scored 0.747 mechanically but received a D grade — the grader found output quality poor despite mechanical completion. Assertions passed (2/2) but grader notes flagged substantive delivery failure. Review assertion coverage for this workflow — the current 2-assertion definition may not catch quality issues.
