## Recommendations

1. **Add output-file existence check before closing state.yaml in daily-review step-auto.** Before writing status: complete, verify reviews/daily/auto-{date}.md exists and is >100 bytes. If absent, set status: partial. This prevents all phantom successes and is the single highest-leverage change in the system.

2. **Fix Slack thread_ts initialization in morning-briefing step-04.** Every July run fails the first send. Investigate whether step-04 reads a stale cached ts from a prior session. Fix initialization order: generate ts after channel verification, not before. Would convert every morning-briefing from partial to success status.

3. **Fix system-eval assertion 001 to check a specific record, not the most-recent glob.** Replace the bare glob with a check against the specific eval record being assessed, or query for the most recent system-eval record with status: success. Current implementation guarantees a false-negative on every run.

4. **Resolve close-eval-record.py session_id mismatch.** Now flagged in two consecutive reports. Add a guard that detects an existing in-progress record with matching name/agent/started-date before creating a new one, and closes that record instead.

5. **Ensure daily-review working memory write cannot be silently skipped.** Add same existence check as recommendation 1 for the WM file. Log explicitly if WM write fails rather than silently continuing to state: complete.

6. **Prompt for Tier 4 feedback on top 3 low-scoring July records.** eval-20260727T171948-S7Z5M6 (watchtower-weekly, 0.577), eval-20260801T021336-KBSSMN (daily-review, 0.508), and eval-20260728T021215-1C4F7E (daily-review, 0.795) have no controller rating. These are the clearest cases where a positive/negative signal would improve model calibration.

7. **Tag general-purpose/fork aborted stubs as a separate corpus segment.** 35 orphaned stubs drag the batch average from ~0.78 (active workflows) to 0.630 (full corpus). Add a corpus_segment field (active | orphaned) and filter orphaned records from the primary dashboard success-rate and score metrics.
