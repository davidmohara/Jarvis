## Recommendations
1. **Add output-write verification guard to daily-review step-auto**: The workflow writes state.yaml complete but skips the output file on ~33% of runs. Add a post-write assertion inside the workflow that checks `reviews/daily/auto-{date}.md` exists before setting status to success. Failing that check should set status to partial, not success.
2. **Investigate the June 19 cascade abort event**: Six general-purpose records aborted in rapid succession (15:17, 15:17, 15:52, 15:52, 15:57, 15:57 UTC). This pattern suggests a session-level failure rather than individual workflow failures. Check session logs for 2026-06-19 afternoon for the root cause.
3. **Fix daily-004 assertion regex**: Pattern `(?i)(priorit|tomorrow|tomorrow's|next)` misses reviews that use 'Q3', 'carry into', 'final window', or date references for forward planning. Broaden to `(?i)(priorit|tomorrow|tomorrow|next|Q[1-4]|next week|carry into|going into)` or split into two assertions.
4. **Resolve morning-briefing partial status**: Both morning-briefing records produce passing output but report partial. Identify which step is not completing and either fix it or update the status-determination logic to reflect partial-but-useful output accurately.
5. **Establish Tier 4 feedback collection cadence**: No record in the corpus has controller feedback. Add a weekly prompt for David to rate 2-3 recent workflow outputs. Even 5-10% feedback coverage would materially improve composite score accuracy and surface real-world quality signals the tier 1-3 model misses.
6. **daily-review working memory write**: Add working memory file write to the daily-review step-auto alongside the review file write. The 2026-06-16 run shows these are handled separately and the WM write is sometimes skipped. Treat both as required outputs.
