# Delegation System Package

**Assembled:** 2026-10-27

## What this package is

A collection of files from the IES repository (Improving Executive System), packaged for grading. Every item is a copy of a live repo file; the originals remain at the source paths listed below. Nothing in this package was written for it — it contains only what already existed.

## Contents and sources

| Item in package | What it is | Source path in the repository |
|---|---|---|
| `submission-draft.md` | Description of the delegation system and where each of its parts lives in the repository | written for this package |
| `index.md` | Contents index mapping each area of the system to its files, plus current measured results | written for this package |
| `CHANGELOG.md` | Release history, v0.1.0 → v1.5.0 | repo root `CHANGELOG.md` |
| `agents/` | Agent definitions: `manifest.md` (roster, roles, owned steps, boundaries), `adversarial-isolation.md`, and the 11 per-agent definition files (master, chief, chase, harper, knox, quinn, ralph, rigby, shep, sterling, galen) | `agents/` |
| `bypass-tests/` | Records of six controlled bypass test runs (BT-01..BT-06), each with a writeup and a run log in `logs/` | `systems/eval-harness/bypass-tests/` |
| `eval-data/audit-exports/` | Per-step model/token/cost audit exports with correlation IDs, one directory per candidate workflow | `systems/eval-harness/audit-exports/` |
| `eval-data/success-rate-*.md`, `.csv` | End-to-end workflow success rates (2026-10-08 baseline and 2026-10-26 recompute), generated by `systems/eval-harness/success-rate.py` | `systems/eval-harness/` |
| `eval-data/adversarial-catches/` | Recorded adversarial review catches from the verification sub-workflows (`catches.jsonl`, `catches.md`) | `systems/eval-harness/adversarial-catches/` |
| `verification/` | The four candidate-workflow adversarial verification sub-workflow definitions | `workflows/<wf>-verification/workflow.md` |

## Candidate workflows

The instrumented workflows are **boot**, **morning-briefing**, **daily-review**, and **plaud-ingest**. Usage data behind this set is in `workflow-rationalization-memo-2026-10-08.md` (repo path `projects/`). **shutdown-cleanup**, the session-exit workflow, is held to the same instrumentation standard though it is not a candidate.

## Not included

- The instrumentation scripts (`step_audit.py`, `export-step-audit.py`, `validate-subagent-output.py`, `success-rate.py`) live in `systems/eval-harness/`; their outputs are included under `eval-data/`.
- Layer 0 schemas: 13 step schemas across boot, morning-briefing, plaud-ingest; daily-review has none (it records no structured outputs). Declared per step at `workflows/<wf>/schemas/`.
- Success-rate figures in `index.md` are from the 2026-10-26 recompute.
